Proksi, rebuilt

Same proxy. A new heart.

Super started with a question: what would Proksi look like on hyper instead of Pingora? Proksi already did the hard parts: certificates that renew themselves, Docker and Kubernetes discovery, plugins, rules, an admin UI. Super keeps all of it.

Your configuration doesn't change. The same config.hcl, environment variables, plugins, stores and metrics. Point Super at Proksi's files and it runs.

What changed is the core. A hyper engine that keeps Pingora's request phases, allocates nothing on the hot path, keeps each connection on its thread, and adds what Pingora can't: HTTP/3 and websockets over HTTP/2.

One file

That's the whole configuration.

Hosts, locations and upstreams, with the blocks you need. Edit it while Super runs: changes apply without dropping a connection.

  • A certificate from Let's Encrypt, renewed before it expires
  • Requests spread across both app servers, retried when one fails
  • HTTP redirected to HTTPS, HTTP/2 and HTTP/3 answered
  • 100 requests a minute per visitor, then a 429
Rules

Ask anything of a request. Pay almost nothing.

A rule is a question about a request, and what to do when the answer is yes. Ask about its method, host, path, query, headers, cookies or client; then redirect it, answer it, limit it, protect it, or send it elsewhere.

~170 nsfor 100 rules
~1.2 µsfor 1,000 rules
~14 µsfor a whole request
  • Compiled when the configuration loads, indexed by method, host and path
  • Each part of a request read once, however many rules ask about it
  • For the whole server, a host, or one location
host "shop.example.com" {
  # Scanners never reach the app
  rule "scanners" {
    and {
      path { contains = ["/.env", "/.git", "/wp-login"] }
    }
    then {
      respond { status = 404 }
    }
  }

  location "/api" {
    upstream "api:4000" {}

    # Reads stay free, writes get a limit
    rule "limit writes" {
      and {
        method { not_in = ["GET", "HEAD"] }
      }
      then {
        rate_limit {
          requests = 60
          per      = "1m"
        }
      }
    }
  }
}

Get started

Running in a minute.

Write a config.hcl, then start Super with Docker, a single binary, or cargo.

# Docker
docker run -d -p 80:80 -p 443:443 -v ./config:/etc/superconfig luizfonseca/super

# Or the binary from GitHub's releases, then
super -c ./config.hcl
